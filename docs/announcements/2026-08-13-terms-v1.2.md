# Terms & Privacy v1.2 — effective 2026-08-13

terakota's License & Terms (EULA), Privacy Notice, and Security Policy move to
**version 1.2, effective 2026-08-13**. The live copies are at
[terakota.io/terms](https://terakota.io/terms),
[terakota.io/privacy](https://terakota.io/privacy), and
[terakota.io/security](https://terakota.io/security); the same texts are in this
repository under [docs/legal/](../legal/) and [SECURITY.md](../../SECURITY.md).

## Why

The upcoming **v1.5.0** release publishes the **Dialpad** read family — three
read-only tools over your Dialpad directory (`dialpad_users_list`,
`dialpad_offices_list`, `dialpad_departments_list`), reached with a Dialpad API
key you supply yourself. It is a third vendor on the read surface, so the terms
name it. Unlike production QuickBooks, it adds no service of ours to any flow:
the key lives in your keystore, the reads run from your machine to Dialpad
directly, and there is no account with us anywhere in the path.

## What changed

- **EULA 1.2.** Dialpad joins the read surface §2 describes, with the BYO-key
  path stated in the same terms as AppFolio: no account with us, no service of
  ours in the path, nothing transmitted to us. Dialpad, Inc. is named in the
  non-affiliation sentence (§2) and in your vendor-agreement responsibility
  (§3(a)). **Section 4's enumerated closed set of connections the Software makes
  to us is unchanged** — Dialpad adds no host of ours.
- **EULA 1.2 discloses the Dialpad surface as snippet-tier**: it is verified
  against a maintainer-held Dialpad tenant only, never on a customer account.
  Nothing in this release claims those tools have run on yours. It also states
  that a Dialpad API key carries whatever scope Dialpad granted it — typically
  more than read — so the key is more capable than the tools that use it.
- **Security Policy 1.2.** Dialpad's systems are named out of scope for security
  testing alongside AppFolio's and Intuit's (§2), and Dialpad's API conduct and
  availability are named in what the policy does not cover (§4). This is a
  correction of omission: the previous text listed only two vendors, and silence
  should not read as an invitation to test a third party's systems.
- **Privacy Notice 1.2.** Dialpad credentials are named in the enumerations that
  were already true of them — the account-free lede, the "makes no call to any
  host of ours" list, the never-transmitted list (§1), and the carve-out in §3a.
  Completeness only; no new collection, no new section.

## What did not change

- No telemetry, no analytics, no crash reporting — still zero.
- Your business data never reaches us. Reads run from your machine to the
  vendor directly, in every mode, Dialpad included.
- AppFolio, Dialpad, and local/sandbox use need no account and send nothing to
  us. Production QuickBooks remains the one path with a service of ours in it,
  on exactly the terms v1.1 set out.
- What the connect service holds is untouched: the account and the eleven-field
  connection record, as disclosed in Privacy §3a.
- The binary remains read-only by construction toward your business systems.

## Timing notes

- These terms are effective on publication. The current release (v1.4.0)
  predates the Dialpad family; this repository's README describes it as shipping
  in v1.5.0, and the tools are not present in any earlier binary.
- v1.5.0 will show its first-run notice again (once) to reflect the new terms
  version, including for existing installs. That is the notice working as
  intended, not a defect; `terakota about` reprints it any time.
